## ANSWER KEY

1. It is a next-token predictor over web text (forum threads continue with more questions); it has no turn-taking or answer behaviour. Start from the **Instruct** variant (T01 §1.2-1.3).
2. r × (d_in + d_out) = 16 × 8192 = **131,072** (0.78% of 16.8M).
3. 2 × 36 × 8 × 128 × 2 B = **144 KB/token**; 32k tokens = 4.5 GB; budget ≈ 72 − 15.3 − 1.5 ≈ 63 GB → **~14** conversations (T06 §2.1).
4. **16 B/param** (2 weights + 2 grads + 4 fp32 master + 8 Adam) → ≈ 128 GB (≈ 122 GiB) for 8.19B (T06 §1).
5. bitsandbytes quantizes `nn.Linear` only; fused 3-D expert tensors stay 16-bit and `prepare_model_for_kbit_training` upcasts non-4-bit tensors to fp32 (T03 §3, P17 §2).
6. No: 21.1 GB leaves ~0.5 GB of the 21.6 GB planning limit. Use QLoRA on 24 GB, or LoRA on a 48 GB card (P03 Section 3).
7. 6 × 8.19e9 × 3.6e7 = 1.77e18 FLOPs; / (989e12 × 0.25) / 3600 ≈ **2.0 H100-hours** (P03 §1.5).
8. **No.** DDP copies the full model to each GPU; only sharding (FSDP/ZeRO-3) reduces per-GPU memory. DDP makes it faster.
9. `data.completion_only_loss: true`: TRL's prompt-completion format masks the prompt and trains the **last assistant turn + its end-of-turn token**, with any template (P10 Section 2).
10. It never learns to stop: it rambles to `max_tokens` (T02 §3).
11. Written first, it cannot be biased by seeing outputs; generated by the same generator from the same documents, a high score only proves the model copies the generator (P05 §2).
12. Exact dedup → heuristic filters → PII scrub/drop → contamination (13-gram) → near-dup (MinHash + LSH) → write + report (T02 §4).
13. Marginals were kept but the feature → target relationship was lost (copula groups too small). Use `--label-mode conditional` (label from P(target | features)) (P07 §6).
14. A constant "shows up" scores 86%; accuracy rewards ignoring the minority class. Use AUC (P07 §6, lesson 3).
15. Raise `--smoothing`: privacy rises, fidelity (PSI) worsens. Find the value where both pass (0.5 in the example).
16. The proxied SSH does not support SCP/SFTP; use "SSH over exposed TCP" (IP + port) (P08 §2B).
17. The difference is inside seed noise: **not a real gain**. Pick the simpler/cheaper config (P12 §4).
18. Every answer in a group gets the same reward → zero advantage → no learning. The task is too hard (all 0) or too easy (all 1): change the prompts or warm up with SFT (T05 §4).
19. Without KL (β = 0) the policy drifted to KL 5.3 and the text degenerated while the reward model's score rose (over-optimising a learned proxy); β = 0.2 kept KL ≈ 1.4 (T05 §2).
20. `--backend endpoint`: a free CPU Space cannot run an 8B model usefully; the Space is only the UI and calls your vLLM server with the key as a secret (or pay for GPU hardware with `--hardware`) (P14 §5).
